# Inbox.EU MCP (Business Premium)

[Руководство на английском языке](./README.md)

Локальный MCP-сервер для администрирования бизнес-почты Inbox.eu. Режим `read-only` открывает 11 инструментов чтения. Режим `full` открывает все 25 операций с описанным назначением, включая удаление аккаунтов и отправку служебных писем. Фактические права определяет Inbox.eu по API-ключу. Требуется Node.js 22 или новее.

MCP-клиент общается с сервером локально через стандартные потоки ввода и вывода (`stdio`). Сервер обращается к Inbox.eu по HTTPS на `https://api.inbox.eu` с проверкой сертификата.

Контрактные тесты используют [локальную копию](./inboxeu-openapi.json) версии 1.0.0, полученную 22 ноября 2026 года. Работающий сервер обращается непосредственно к API. [Исходная спецификация Inbox.eu](https://api.inbox.eu/api/v1/doc.json)

## Установка и запуск

Установите Node.js 22 или новее. Склонируйте репозиторий и перейдите в каталог проекта.

```sh
git clone https://github.com/xcodebasex/Inbox.EU-MCP-Business-Premium.git InboxeuMCP
cd InboxeuMCP
```

Можно также скачать ZIP-архив со страницы репозитория, распаковать его и открыть терминал в каталоге с `package.json`. [Репозиторий на GitHub](https://github.com/xcodebasex/Inbox.EU-MCP-Business-Premium)

Установите зависимости и создайте `.env` из шаблона, если файла ещё нет.

**Windows (PowerShell)**

```powershell
npm.cmd ci --ignore-scripts
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
```

**Linux и macOS**

```sh
npm ci --ignore-scripts
if [ ! -e .env ]; then cp .env.example .env; fi
```

Для проверки установки можно запустить тесты командой `npm.cmd test` в PowerShell или `npm test` в Linux и macOS. Тесты используют локальные данные.

Создайте API-ключ для подтверждённого домена в Inbox.eu Business и впишите его после `INBOXEU_API_KEY=` в `.env`. Для начала оставьте `INBOXEU_MODE=read-only`. Дайте учётной записи сервера доступ на чтение файла и ограничьте доступ посторонних пользователей и процессов. [Шаблон .env.example](./.env.example) · [Выдача ключа](https://a.inbox.eu/en/api_access/)

Чтобы запустить сервер вручную, выполните в каталоге проекта следующую команду.

```sh
node src/index.js
```

При обычном запуске сервер ничего не выводит и ожидает запросы MCP на стандартном входе. Чтобы остановить его в терминале, нажмите `Ctrl+C`.

## Установка плагина в ChatGPT Desktop

Плагин работает в локальных чатах настольного приложения в режиме **Work**. После установки зависимостей и настройки `.env` по инструкции выше выполните команду в каталоге с `package.json`.

```sh
npm run plugin:desktop
```

В Windows PowerShell можно использовать `npm.cmd run plugin:desktop`.

1. Перезапустите ChatGPT Desktop и откройте папку проекта в режиме **Work**.
2. Откройте **Plugins**, выберите **Inbox.eu Local** в списке каталогов и установите **Inbox.eu Business**. [Руководство OpenAI по локальному каталогу плагинов](https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually)
3. В новом локальном чате проекта в режиме **Work** введите `@Inbox.eu` и выберите **Inbox.eu Business** в разделе **Plugins**. Попросите «Вызови `inboxeu_check_auth` с аргументами `{}`». При действующем ключе вы получите `{"authenticated":true}`. Чтобы проверить установку до добавления ключа, попросите перечислить инструменты Inbox.eu. В режиме `read-only` по умолчанию их одиннадцать. [Выбор плагина в Work](https://learn.chatgpt.com/docs/build-plugins#using-a-plugin)

Плагин находит `node` через системную переменную PATH и запускает существующий `src/index.js`. Сервер читает исходный `.env` рядом с `package.json`. Результаты вызовов, которые получает ChatGPT, могут содержать сведения о почтовых ящиках. Если вы переместили проект, повторите команду подготовки из нового каталога и переустановите плагин. Если ChatGPT не находит Node.js, добавьте его в PATH и перезапустите настольное приложение.

### Обновление установленного плагина

Если вы клонировали проект через Git, выполните в его каталоге следующие команды.

```sh
git pull --ff-only
npm ci --ignore-scripts
npm run plugin:desktop
```

Если вы устанавливали проект из ZIP-архива, распакуйте новую версию, поместите свой `.env` рядом с её `package.json` и выполните в этой папке две команды npm из примера выше.

Полностью закройте ChatGPT Desktop, снова откройте обновлённый проект в режиме **Work** и переустановите **Inbox.eu Business** из каталога **Inbox.eu Local**. Это заменит старый процесс сервера, который мог продолжать использовать пустой ключ даже в новом чате. Команда подготовки создаёт локальный файл `plugins/inboxeu-business/mcp.json` с путём к серверу. Ключ хранится в `.env` проекта.

Выберите плагин через `@` и вызовите `inboxeu_check_auth` с аргументами `{}`. Ожидаемый ответ — `{"authenticated":true}`. Если инструмент сообщает `Set INBOXEU_API_KEY to a key with no spaces or line breaks.`, проверьте строку `INBOXEU_API_KEY` в `.env` этого проекта. После обновления можно добавить, заменить или удалить ключ и сразу повторить вызов в том же чате. При изменении режима доступа или параметров инструментов по умолчанию перезапустите сервер.

Если плагин уже подключён к обычному ChatGPT через Secure MCP Tunnel, перезапустите клиент туннеля, который запускает этот MCP-сервер. В настройках плагина в ChatGPT нажмите **Refresh tools** («Обновить инструменты») и проверьте, что среди инструментов чтения появился `inboxeu_list_mailboxes`.

## Подключение MCP-клиента

В клиенте с поддержкой локальных MCP-серверов выберите транспорт `stdio`, укажите команду `node` и передайте абсолютный путь к `src/index.js` первым аргументом. Если клиент использует JSON с разделом `mcpServers`, добавьте такую запись, заменив путь в примере своим.

```json
{
  "mcpServers": {
    "inboxeu": {
      "command": "node",
      "args": ["C:/Projects/InboxeuMCP/src/index.js"]
    }
  }
}
```

В Linux или macOS путь может выглядеть как `/home/alex/InboxeuMCP/src/index.js` или `/Users/alex/InboxeuMCP/src/index.js`. После сохранения настроек подключите сервер в клиенте. Клиент сам запустит дочерний процесс и будет обмениваться с ним сообщениями через `stdio`.

Вызовите в клиенте метод MCP `tools/list`. В режиме `read-only` сервер вернёт 11 инструментов. Список доступен и без API-ключа. Чтобы проверить сам ключ, вызовите `inboxeu_check_auth` с аргументами `{}`. При действующем ключе вы получите `{"authenticated":true}`.

Сервер читает все настройки `INBOXEU_*` из одного файла. По умолчанию это `.env` рядом с `package.json` независимо от рабочего каталога клиента. Если храните `.env` в другом месте, добавьте в `args` аргумент `--env-file` и абсолютный путь к файлу. Тогда сервер прочитает только выбранный файл. `.env.example` служит шаблоном.

Если ключ ещё не был задан или вы его заменили, сохраните новое значение `INBOXEU_API_KEY` в выбранном файле и снова вызовите `inboxeu_check_auth` в том же чате. Сервер читает ключ перед каждым запросом к API. После изменения других настроек, в том числе режима доступа, домена или ящика по умолчанию, перезапустите MCP-сервер.

## Выбор режима

Установите `INBOXEU_MODE=read-only` или `INBOXEU_MODE=full` в `.env` и перезапустите MCP-сервер. В режиме чтения инструменты записи отсутствуют в каталоге, а прямой вызов по их имени отклоняется до обращения к API.

Для отдельного запуска режим можно задать в командной строке. В примере сервер загружает настройки из указанного файла и работает в режиме чтения, даже если в файле выбран `full`. Выполните команду из каталога проекта, подставив абсолютный путь к своему файлу. Эти же параметры можно добавить в массив `args` клиента после пути к `src/index.js`.

```sh
node src/index.js --env-file "C:/Private/InboxeuMCP/.env" --mode read-only
```

Аргумент `--mode` имеет приоритет над `INBOXEU_MODE` из выбранного файла. Если оба значения пропущены, действует `read-only`. Неизвестное значение режима или недоступный явно указанный файл останавливает запуск. Для перехода со старого `INBOXEU_ENABLE_WRITES=true` выберите `full` явно.

## Поиск ящика по адресу

Укажите `INBOXEU_API_KEY` в локальном `.env` рядом с `package.json` и запустите сервер в режиме `read-only`. В ChatGPT выберите **Inbox.eu Business** и спросите «Какой статус у ящика info@example.org?». Подставьте адрес в домене, к которому ключ администратора имеет доступ. В другом MCP-клиенте вызовите `inboxeu_get_mailbox` с такими аргументами.

```json
{"mailboxEmail":"info@example.org"}
```

Сервер берёт домен из адреса, загружает по HTTPS список его ящиков и находит внутренний ID. Затем он получает карточку ящика, сверяет её с запрошенным адресом и возвращает `data.email` и `data.id`. Если адрес отсутствует в списке, инструмент сообщает об этом. При ошибке доступа к API статус ящика остаётся неподтверждённым. Поиск выполняется по запросу в выбранном домене. Полученный список не сохраняется на диск.

Чтобы узнать доступные ключу домены, спросите «Перечисли мои домены в Inbox.eu» или вызовите `inboxeu_list_domains` с `{}`. В массиве `domains` вернутся имена доменов.

Чтобы посмотреть адреса и внутренние ID, спросите «Перечисли почтовые ящики домена example.org и их ID» или вызовите `inboxeu_list_mailboxes` с `{"domainName":"example.org"}`. В каждой записи массива `data` есть `email`, строковый `userId` и, если его вернул Inbox.eu, `status`. В ответе также есть `total`, `offset` и `nextOffset`. Для следующей страницы передайте полученный `nextOffset` в аргументе `offset`. По умолчанию на странице до 100 ящиков, допустимый `limit` — от 1 до 100. Чтобы при таком вызове пропускать домен, задайте `INBOXEU_DOMAIN_NAME=example.org` в `.env`. Если в настройках нет доменов, сервер может загрузить доступные ключу домены, выбрать единственный или предложить выбрать из нескольких. При запросе карточки почтового ящика по одному домену сервер сначала проверит настроенные для него ящики. При отсутствии подходящих настроек он запросит список ящиков домена. Если ящик один, сервер выберет его сам. При нескольких ящиках он предложит выбрать нужный по адресу и ID, а при пустом списке сообщит об этом.

Если ключу доступна карточка ящика, а чтение списка ограничено, укажите оба значения, например `{"mailboxEmail":"info@example.org","userId":"00123"}`. Ранее сохранённые в `INBOXEU_DOMAINS` соответствия продолжают работать. При явно переданном или настроенном ID сервер сразу читает карточку и сверяет адрес.

## Параметры инструментов в .env

Чтобы выбрать ящик по умолчанию для вызовов без аргументов, заполните две строки в загружаемом `.env` и перезапустите MCP-сервер. После этого можно вызвать `inboxeu_get_mailbox` с `{}`. В примере подставьте домен и внутренний ID своего ящика.

```dotenv
INBOXEU_DOMAIN_NAME=example.org
INBOXEU_USER_ID=00123
```

`INBOXEU_DOMAIN_NAME` задаёт домен в путях API, а также имя домена для проверки и приглашения администратора. `INBOXEU_USER_ID` задаёт ID ящика, `INBOXEU_DOMAIN_ADMIN` — ID администратора. При создании администратора поле `domainName` принимает отдельный JSON-объект. Остальные переменные сгруппированы по инструментам в [.env.example](./.env.example).

Строки, включая ID с ведущими нулями, вводите как текст. Для целых чисел и логических значений используйте запись JSON, например `20`, `true` или `false`, с учётом ограничений конкретного поля. Массивы и объекты удобно заключить в одинарные кавычки снаружи и использовать двойные кавычки внутри.

```dotenv
INBOXEU_LIST_INVOICES_LIMIT=20
INBOXEU_CREATE_ADMIN_IS_EMAIL_VERIFIED=false
INBOXEU_CREATE_ADMIN_DOMAIN_NAME='{"name":"example.org","mailboxUsernames":["office"]}'
INBOXEU_UPDATE_PROFILE_PREFS='{"itemsPerPage":50}'
INBOXEU_CREATE_MAILBOXES_BODY='[{"user":"office"}]'
```

Значение из вызова заменяет всё соответствующее поле, включая объект или массив целиком. Например, `{"limit":5}` в вызове `inboxeu_list_invoices` переопределит лимит и сохранит домен из `.env`. Пустые настройки в `.env` сервер пропускает. После изменения этих параметров по умолчанию перезапустите MCP-сервер.

При чтении данных существующего домена сервер в первую очередь учитывает явно заданный домен или настройки. Если в `.env` нет списка доменов, он может запросить их у Inbox.eu. Когда есть несколько вариантов, сервер уточнит выбор. Для проверки доступности доменного имени укажите интересующее имя или ответьте на вопрос сервера. Для операций записи укажите ящик при вызове или задайте его в `.env`. Сервер спросит недостающий домен или ID ящика.

Если MCP-клиент поддерживает формы, он предложит ввести значение вручную и покажет подсказки из `.env`, когда они есть. При отказе или отмене формы сервер завершит вызов без обращения к Inbox.eu. Клиент без поддержки форм получит вопрос на английском. После ответа пользователя клиенту нужно повторить вызов, добавив запрошенный аргумент. Сервер проверяет итоговые аргументы до обращения к API.

Заполненные поля записи, включая пароль или адрес получателя, применяются при каждом вызове соответствующего инструмента, если вы их не переопределили. Для разовой операции передайте такие значения в самом вызове. При смене домена проверьте, что указанный ID ящика принадлежит этому домену.

### Один ключ для нескольких доменов

Если один ключ даёт доступ к нескольким доменам, запишите его один раз в `INBOXEU_API_KEY`. Для списка доменов используйте JSON-массив в `INBOXEU_DOMAINS`.

```dotenv
INBOXEU_DOMAINS='["example.org","example.net"]'
```

При необходимости можно явно сохранить соответствия для части ящиков. Для каждого такого ящика укажите под его доменом часть адреса до `@` и внутренний ID. В панели Inbox.eu Business откройте список ящиков домена и найдите ссылку редактирования нужного адреса. Скопируйте ID из пути `/users/<userId>/…`. Записывайте ID в кавычках, чтобы сохранить ведущие нули.

```dotenv
INBOXEU_DOMAINS='{"example.org":{"info":"00123","sales":"00456"},"example.net":{"office":"00789"}}'
```

Перезапустите сервер после изменения настроек. Например, для `info@example.org` из такой конфигурации сервер сразу запросит `00123`. Для адресов без сохранённого ID он найдёт ящик через список домена. Для совместимости клиент может передать полный адрес в поле `userId` при чтении одного ящика.

Для поиска только по ID можно по-прежнему использовать списки, например `INBOXEU_DOMAINS='{"example.org":["00123","00456"],"example.net":["00789"]}'`. Домен по умолчанию задаёт `INBOXEU_DOMAIN_NAME`. Если эта переменная пуста и в списке ровно один домен, сервер выберет его автоматически.

При заполненном `INBOXEU_DOMAINS` сервер подбирает ящик только в выбранном домене. Для основного домена можно задать ящик по умолчанию в `INBOXEU_USER_ID`. Если у этого домена есть непустой список ID, значение `INBOXEU_USER_ID` должно входить в него. Без заданного ящика по умолчанию сервер подставит единственный ID выбранного домена.

В примере с JSON-объектом вызов `inboxeu_get_mailbox` с `{"domainName":"example.net"}` выберет ящик `00789`, даже если для основного домена `example.org` задан `INBOXEU_USER_ID=00123`. Второй ящик в `example.org` можно выбрать прямо при вызове.

```json
{"domainName":"example.org","userId":"00456"}
```

Вы можете явно указать домен и ID вне списка. При переключении между доменами сервер использует тот же ключ, а доступ к выбранному ящику проверяет Inbox.eu. Перезапуск при таком вызове не требуется.

### Токен входа и отправка сведений о ящике

Эти настройки нужны только для соответствующих инструментов в режиме `full`. В режиме `read-only` их можно оставить пустыми. Записывайте каждую переменную на отдельной строке без завершающего `\`.

При непустом `INBOXEU_DOMAINS` сервер подставляет `INBOXEU_IMPERSONATION_TOKEN` только для ящика по умолчанию. Его определяют домен по умолчанию и `INBOXEU_USER_ID` либо единственный ID в списке этого домена. Для другого ящика или при отсутствии ящика по умолчанию передайте выданный нужному ящику токен в аргументе `impersonationToken`.

| Переменная в `.env` | Что указать и где взять значение |
| --- | --- |
| `INBOXEU_IMPERSONATION_TOKEN` | Токен входа в конкретный ящик. Чтобы получить его, вызовите `inboxeu_create_impersonation_token` с доменом, внутренним ID ящика и телом `ApiMailUser`. Скопируйте значение поля `structuredContent.impersonationToken` из ответа. Для разовой проверки передайте его как аргумент `impersonationToken` того же ящика. Ключ администратора хранится отдельно в `INBOXEU_API_KEY`. |
| `INBOXEU_VALIDATE_IMPERSONATION_TOKEN_BODY` | JSON-объект `ApiMailUser` для проверки токена. В документации откройте раздел **Mailbox users** → `POST …/impersonation/validate` → **Request body**. В эту переменную запишите тело запроса. Сам токен передаётся отдельно через `INBOXEU_IMPERSONATION_TOKEN`. |
| `INBOXEU_VALIDATE_IMPERSONATION_TOKEN_IMPERSONATION_TOKEN` | Это имя MCP игнорирует. Оставьте нужный токен в одной строке `INBOXEU_IMPERSONATION_TOKEN`, затем удалите строку с длинным именем. |
| `INBOXEU_SEND_MAILBOX_DETAILS_BODY` | JSON-объект `MailUserDetails` для служебного письма со сведениями о созданном или изменённом ящике. В документации откройте **Send details for mailbox users** → `POST …/details` → **Request body**. Перед отправкой проверьте адрес получателя в подготовленном теле запроса. |

Inbox.eu публикует для обеих схем только тип «объект». Чтобы узнать точные поля, включая поле адресата для письма, возьмите тело успешного запроса к тому же методу из своей интеграции или запросите образец у `support@inbox.eu`, указав метод и название схемы. Сохраните этот JSON в одинарных кавычках в `.env` и перезапустите MCP. [Документация Inbox.eu](https://api.inbox.eu/api/v1/doc/) · [Схемы OpenAPI](https://api.inbox.eu/api/v1/doc.json)

## Инструменты

Одиннадцать инструментов чтения обращаются к административному API Inbox.eu Business по HTTPS. В описании Business API Inbox.eu указывает, что можно получать списки доменов и ящиков. В рабочем API запрос `GET /api/v1/domains/` возвращает домены, а `GET /api/v1/domains/{domainName}/mail_users/` — ящики с разбивкой на страницы. Эти маршруты пока отсутствуют в опубликованной спецификации OpenAPI. [Описание Business API](https://www.inbox.eu/en/inbox-eu-api/) Успешный поиск ящика подтверждает, что Inbox.eu вернул его учётную запись. Чтение папок и писем и проверка доставки выходят за рамки опубликованного API. [Спецификация OpenAPI Inbox.eu](https://api.inbox.eu/api/v1/doc.json)

| Инструмент | Вход | Результат |
| --- | --- | --- |
| `inboxeu_check_auth` | — | Проверка API-ключа |
| `inboxeu_get_profile` | — | Профиль текущего администратора |
| `inboxeu_get_2fa_status` | — | Флаг `isEnabled` для двухфакторной аутентификации |
| `inboxeu_get_admin` | `domainAdmin` | Профиль администратора по ID. Если Inbox.eu отклонит общий запрос, инструмент проверит домен по умолчанию или единственный настроенный домен. Если домен определить не удалось, он проверит профиль текущего администратора. В обоих случаях ID должен совпасть с запрошенным. |
| `inboxeu_get_domain_admin` | `domainName`, `domainAdmin` | Профиль администратора указанного домена |
| `inboxeu_list_domains` | Нет | Возвращает имена доступных по ключу доменов в массиве `domains`. |
| `inboxeu_list_mailboxes` | `domainName`, необязательные `limit` и `offset` | Постраничный список адресов и внутренних ID ящиков выбранного домена. |
| `inboxeu_get_mailbox` | `mailboxEmail` либо `domainName` и `userId` | Административные сведения об одном ящике. При поиске по адресу сервер при необходимости загружает внутренний ID и сверяет карточку с запросом. |
| `inboxeu_list_invoices` | `domainName`, опционально `limit`, `offset`, `unexpired`, `order_column`, `order_direction` | Страница счетов домена |
| `inboxeu_check_domain` | `hostName` | `available` показывает, свободно ли имя в базе Inbox.eu |
| `inboxeu_check_admin_email` | `email` | Показывает, доступен ли адрес для **регистрации администратора**. Для проверки самого ящика используйте `inboxeu_get_mailbox`. |

Например, для первой страницы счетов передайте `{"domainName":"example.org","limit":20,"offset":0}`. Для следующей страницы увеличьте `offset` на число полученных записей. Сумма сохраняет исходное строковое представление и сопровождается валютой, если API её вернул.

### Дополнительные инструменты режима full

| Инструмент | Вход |
| --- | --- |
| `inboxeu_create_admin` | Обязательные `email` и `language`. Опционально `firstName`, `lastName`, `password`, `euRefId`, `isEmailVerified` и объект `domainName` с `name` и/или `mailboxUsernames`. Если пароль опущен, Inbox.eu отправит сгенерированный пароль по email. Для `isEmailVerified` требуются специальные права. |
| `inboxeu_update_profile` | Хотя бы одно из полей `firstName`, `lastName`, `language`, `prefs`, `plainPassword`, `tos`. В настройках доступны `itemsPerPage`, `userSortField`, `userSortOrder`. |
| `inboxeu_invite_admin` | `email`, `user`, `hostname`. Inbox.eu отправит приглашение администратору. |
| `inboxeu_delete_profile` | Без параметров. Удаляет аккаунт администратора, которому принадлежит API-ключ. |
| `inboxeu_remove_domain_admin` | `domainName`, `domainAdmin`. Отзывает доступ администратора к одному домену. |
| `inboxeu_enable_2fa`, `inboxeu_disable_2fa` | Без параметров. Меняют настройку текущего администратора. При включении MCP возвращает полученные от API данные для регистрации в приложении-аутентификаторе. |
| `inboxeu_create_mailboxes` | `domainName`, `body` — массив объектов `ApiMailUser`. В `summary.succeeded` и `summary.failed` указано, сколько ящиков создано и сколько запросов отклонено. Для отклонённой записи поле `message` поясняет причину, в том числе достижение лимита ящиков, если Inbox.eu сообщил об этом. |
| `inboxeu_update_mailbox` | `domainName`, `userId`, `body` — объект `ApiMailUser`. Для изменения имени и фамилии ящика Inbox.eu принимает поля `forename` и `surname`. |
| `inboxeu_delete_mailbox` | `domainName`, `userId`. Удаляет указанный ящик. |
| `inboxeu_send_mailbox_details` | `domainName`, `userId`, `body` — объект `MailUserDetails`. Запрашивает у Inbox.eu отправку письма со сведениями о ящике. |
| `inboxeu_update_mailbox_filters` | `domainName`, `userId`. Документация описывает PUT-запрос только с этими параметрами. |
| `inboxeu_create_impersonation_token` | `domainName`, `userId`, `body` — объект `ApiMailUser`. Возвращает полученный токен для входа в указанный ящик. |
| `inboxeu_validate_impersonation_token` | Те же параметры и строка `impersonationToken`. Если действительность токена определить не удалось, сервер возвращает `valid: null` и пояснение в поле `message`. |

Типы и допустимые значения доступны через `tools/list`. Для `ApiMailUser` и `MailUserDetails` провайдер публикует тип «объект» без списка полей. MCP передаёт предоставленный JSON в теле соответствующего запроса. Для изменения фильтров схема тела не опубликована. Семь дополнительных записей для `/domain_admins/{domainAdmin}` содержат только пустой ответ `default` без описания назначения и результата. [Контракт Inbox.eu](https://api.inbox.eu/api/v1/doc.json)

### Какие письма можно отправить

Через API можно попросить Inbox.eu отправить приглашение администратору или сведения о созданном либо изменённом ящике. При создании администратора без поля `password` Inbox.eu также отправляет сгенерированный пароль по электронной почте. Для обычных писем со своими адресатом, темой и текстом нужно отдельное подключение к почте. [Документация Inbox.eu](https://api.inbox.eu/api/v1/doc/)

## Ответы и диагностика

- Сервер отправляет ключ в заголовке `Authorization: Bearer`. Адрес API фиксирован. Переадресация отключена, в том числе на HTTP. При отключённой в Node.js проверке TLS-сертификатов сервер отклоняет запрос до отправки.
- При сбое вызова MCP возвращает `isError: true` и короткое пояснение на английском. Если сервис отклонил ключ, проверьте `INBOXEU_API_KEY`. Если для операции недостаточно прав, проверьте доступ администратора к домену. При ограничении частоты запросов повторите попытку позже.
- Если Inbox.eu явно сообщает, что адрес свободен для регистрации администратора, инструмент возвращает `available: true`. При нераспознанной ошибке инструмент сообщает о сбое. Проверка домена показывает только доступность имени в базе Inbox.eu. [Описание методов](https://api.inbox.eu/api/v1/doc/)
- При чтении профилей, счетов и статуса двухфакторной аутентификации сервер исключает ключи, пароли и секреты. Данные настройки двухфакторной аутентификации и токен входа возвращаются клиенту при явном вызове соответствующего инструмента в режиме `full`.
- На каждый запрос к API отводится до 15 секунд, предел тела ответа — 1 МиБ. Если соединение оборвалось после отправки записи, проверьте её результат в панели Inbox.eu перед ручным повтором. Для большого списка счетов уменьшите `limit`.
- Результат операции доступен в `structuredContent`. Для отказа или неподтверждённого изменения текстовый блок `content` содержит короткое пояснение, для частично выполненного пакета — сводку. Результаты отдельных ящиков остаются в `structuredContent.data`.
